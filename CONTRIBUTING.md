# Contributing to the vehicle registry

Thank you for helping. The registry is meant to stay **small and carefully reviewed**: every fact must be checkable and
every file must be useful to many people, so the rules below are strict.

## What belongs here

- **Production models** with facts from the factory that anyone can check in a public source: wheel bolt pattern, hub
  bore, stock wheel diameter, drive modes. Only what you can cite; leave out anything you cannot.
- **Templates**: the list of setup parameters that suits a kind of car (generic: street, track) or a production model
  generation (with `appliesTo`).
- **Generic modifications**: packages that add, change or remove parameters for a kind of change any car can have
  (coilovers with 1 to 4 damping ways, camber plates, a rear wing, a brake bias adjuster, an engine remap).

## What does not belong here

- Specific parts or brands (a particular coilover, wing or tyre model) and modifications named after them.
- Variants built by users, one-off cars and personal data of any kind.
- Setups (`kind: "setup"`): the values someone used are shared as files, not through this registry.
- Data copied from manufacturer applications, configurators or databases without a licence that allows it, and data
  under non-commercial or share-alike licences.

## Pull requests

- **One model, template or modification per pull request.** A model file and the template it points to may go together.
- **Do not edit `dist/`.** The index is regenerated by the continuous integration after a merge; a pull request that
  touches `dist/` fails its checks.
- Run `dotnet run --project tools/OrfVehicles -- validate .` before you open the pull request. The same check runs in
  the continuous integration.

## Model files

- The id is `<make>/<model>` and the file is `models/<make>/<model>.json`. Ids use `a-z`, `0-9` and single `-`, 2 to 32
  characters per part.
- A model has variants (`base`, `sport`) and each variant has generations (`gen1`, `gen2`), with the years they were
  built (`from`, and `to` once production ended). The generation id `<make>/<model>/<variant>@<generation>` is what
  `appliesTo` refers to.
- Generate every `uid` (model and generations) with `dotnet run --project tools/OrfVehicles -- uid`. **A uid never
  changes**, not even when an id is renamed.
- Every model file of a make repeats the same `make` block (`id`, `name`, `external`).
- `stock` holds only facts of the production car, in the units of the field names (`hubBoreMm` in millimetres,
  `wheelDiameterIn` in inches; `boltPattern` as `<studs>x<pitch circle diameter in mm>`, for example `5x114.3`).
- `template` names the template in `templates/` that suits the generation, when there is one.

## Templates and modifications

- `.runsetup` files of Open Run Format 1.3 or later (section 11 of the specification), saved as
  `templates/<id>.runsetup` (`kind: "template"`) or `modifications/<id>.runsetup` (`kind: "modification"`).
- Use the standard vocabulary of the specification where it fits; any other key starts with `x-` and carries a
  description with names in as many languages as you can.
- Raise `version` with every change. Never reuse an id for something different.
- A generic modification has no `appliesTo` (or an empty one) and must compose with every template.

## Provenance

Every model file lists where its facts come from in `provenance`:

| `method` | What | Requirements |
|---|---|---|
| `official` | Published by the manufacturer (press kit, owner's manual, specification sheet) | `source` or `url` |
| `published` | Another public source (a reference work, a public database such as Wikidata) | `source` or `url`; `attribution` for CC BY |
| `measured` | Your own measurement of a production car | `contributor`, `date` |

Facts are not copied as text: a contributor reads the source and records the values. When a source has a licence, it
must be `CC0-1.0` or `CC-BY-4.0` (with its `attribution` text).

## External ids

`external` links a make (scope `make`) or a model (scope `model`) to an id in a public database (`wikidata` today). Link
only the item itself; do not copy lists from the database. To accept a new system, open a pull request that adds it to
`schema/systems.json` and explain why the identifier is public and what licence the database uses.

## Review checklist (maintainers)

- [ ] Every stock fact is in a public source listed in `provenance`; nothing that cannot be checked.
- [ ] No part brands, user variants, setups or personal data.
- [ ] Ids follow the rules above; no uid was changed; the generation years make sense.
- [ ] New `x-` parameters have clear names and are not already in the standard vocabulary.
- [ ] Changed templates and modifications have a higher `version`.
